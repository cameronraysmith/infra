# Comment cleanup

## Scope

This skill is the operational enforcement arm of the code-comments policy defined in `preferences-style-and-conventions` §"Code comments"; it does not restate that policy but drives it over real trees.
It is a workflow sibling to `preferences-git-history-cleanup`, and like it, a comment-only cleanup is a legitimate standalone change.

## The tool: uncomment

The workflow is built on this repository's `uncomment-bin` package (`pkgs/by-name/uncomment-bin`), a tree-sitter comment remover whose bare invocation is allow-by-default, not deny-by-default: it preserves TODO, FIXME, HACK, XXX, NOSONAR, the `~keep` marker, doc comments, and linting directives (eslint-disable, clippy::, noqa, and similar) unless told otherwise, and removes everything else.
`--remove-todo`, `--remove-fixme`, and `--remove-doc` opt back into removing those specific preserved categories one at a time, and `--no-default-ignores` drops every built-in preservation rule at once, which is the only invocation that behaves deny-by-default.
It offers `--dry-run` and `--dry-run --diff` (no writes), a `~keep` always-preserve escape hatch, and case-insensitive substring `preserve_patterns` in a `.uncommentrc.toml` (global merges into per-language).
It reliably emits a "warning: removed N potentially important comment(s). Re-run with --dry-run --diff to inspect." message when `--no-default-ignores` strips a built-in-protected comment; on a large, heterogeneous tree it can also fire under plain default flags (verified against this repository), so its absence on a small or clean run is not evidence the diff needs no review.
The behavior this section and the rest of this skill describe was established against `uncomment-bin` 3.6.0.

## Why uncomment is never run unattended

uncomment cannot be a repo-wide mutation engine; linting and formatter directives (`fmt: off`/`fmt: on`, `prettier-ignore`, `eslint-disable`, `noqa`, `type: ignore`, `shellcheck disable`, and the rest of that family) are preserved by default anywhere in a file — confirmed by placing one past line 10 — not only near the top.
SPDX/license/copyright lines and code-generation "DO NOT EDIT"/"Generated by" markers are also preserved by default as of 3.6.0, but that protection stays capped to roughly the first 10 lines of a file, confirmed by moving an identical marker from line 9 to line 13 and watching it start getting removed, so these markers are unprotected outside that header window.
It misses `# SAFETY:` and `# -*- coding: utf-8 -*-` by default — no built-in pattern recognizes either — and it intrinsically deletes hand-written "why" prose that carries none of its recognized keywords, which is the exact rationale category the policy protects and the real reason a human-plus-agent classification gate stays between census and apply.
Its language list is not an allowlist (shell, yaml, python, javascript, and rust were all processed in the same run during verification), and while it now respects `.gitignore` by default, there is no config key that blanket-excludes a path from processing: a committed-but-generated or vendored tree that is not gitignored is walked and modified like any other source and must still be excluded by path, one subtree at a time.

## The workflow

Operate on one subdirectory tree at a time rather than the whole repository, e.g. `uncomment modules/apps --dry-run --diff`.

### 1. Census

If the target tree has no `.uncommentrc.toml` and touches languages the hardened `uncommentrc.toml` config doesn't cover, run `uncomment init --comprehensive` first to generate a project-scoped baseline, then layer the hardened config's residual-gap patterns (`SAFETY:`, the coding declaration) on top.
Take a complete candidate-removal inventory without touching files.
The "important" counter is not a reliable census seed either way — it usually stays silent on a default-flags run but can surface on a large tree, and it never appears at all on some runs that still contain real losses — so treat every removed line in the diff as a classification candidate regardless of whether a warning showed up.
On a large subtree, add `-j 0` to auto-detect the thread count instead of the default single-threaded scan.

```bash
uncomment modules/apps --dry-run --diff -j 0
```

### 2. Classify

Fan out the candidate removals across parallel agents, sorting each into `mandatory-keep`, `essential-keep`, or `slop-cut`, seeded by the `preferences-style-and-conventions` §"Code comments" load-bearing carve-out list.
When a recurring pattern needs to be spared for this run without editing the shared config, re-run census with `-i "<pattern>"` to confirm the narrower diff before committing to that classification.
Adversarially verify every proposed cut before applying, treating a wrong deletion of a rationale comment as high-severity.

### 3. Apply

Delete only confirmed slop, in place; essential and mandatory comments never move, so there is no lossy strip-then-restore round trip.
Run the real removal with `-q/--quiet` once the diff has already been reviewed in census, since apply no longer needs the per-file output or inline diff that step produced.

### 4. Commit

Group the applied cuts by subsystem into a small number of atomic commits; never commit one comment per commit.

## Safety gates

Exclude vendored, generated, and upstream-mirrored trees that are not already gitignored by path, since uncomment has no config key for blanket path exclusion and its language list is not an allowlist.
Watch for cross-branch file collisions with any active VCS chains, and keep dry-run-first discipline before every apply.
A hardened starting config ships beside this skill at `uncommentrc.toml`.
3.6.0 already preserves formatter and linting pragmas by default anywhere in a file, and preserves SPDX/license/copyright lines and "DO NOT EDIT"/"Generated by" markers by default within roughly the first 10 lines, so the config now only needs to close what's still missing at any position: `SAFETY:`, the `-*- coding: -*-` declaration, `WORKAROUND`, `XXX`, bare copyright symbols, bare "generated" markers without the recognized phrasing, and managed-block sentinels.
Copy it to the target repository root as `.uncommentrc.toml` and treat it as a targeted-assist config for a specific run, not a standing repo-wide policy.
